# Contributing to Cowlick

Thank you for helping make AI-assisted engineering more reliable and useful.

## Before contributing

- Search existing issues and pull requests before starting duplicate work.
- Open an issue before a large or breaking proposal.
- Keep changes focused on one problem.
- Never submit secrets, private data, or generated content you cannot license.
- Follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Pull requests

1. Fork the repository and create a short-lived branch.
2. Update the relevant documentation and examples with the change.
3. Verify every command, link, and claim you changed.
4. Explain the problem, the smallest solution, and how you verified it.
5. Confirm that your contribution can be distributed under Apache-2.0.

Maintainers may ask for changes or close proposals that add unnecessary
complexity, duplicate existing guidance, or conflict with Cowlick's principles.

## Decisions

Normal changes use issues and pull requests. Changes to core principles,
governance, or compatibility should begin as a public RFC issue before code or
documentation is merged.
